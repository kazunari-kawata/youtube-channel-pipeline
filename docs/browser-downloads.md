# ブラウザ経由の素材の取得（fbi.gov など、クラウドから届かないサイト）

fbi.gov、vault.fbi.gov、usmarshals.gov、floridamemory.com は、クラウドと Windows の作業用シェルからの取得を拒む（403 や確認の画面）。
ユーザーの Windows の Chrome（Claude in Chrome）なら開ける。2026-11-28 の 006 で手順を決めた。

## 一度だけの設定（ユーザー）

1. Chrome の設定 →「ダウンロード」→「ダウンロード前に各ファイルの保存場所を確認する」をオフ
2. Chrome の設定 →「プライバシーとセキュリティ」→「サイトの設定」→「その他の権限」→「自動ダウンロード」に、
   `www.fbi.gov`、`www.usmarshals.gov`（ほかに使うサイトも）を「許可」で足す。これがないと、2つ目からのダウンロードが止まる
3. Claude のデスクトップアプリで、会話に Windows の「ダウンロード」フォルダを追加する（「+」→「フォルダを追加」）。
   アクセスの確認の画面が出たら許可する（2026-11-28 は確認の画面が時間切れで2回閉じた）

## 取り方（Claude）

1. 保存の前に、ファイル名・取得元・大きさをユーザーに伝えて許可をもらう（CLAUDE.md、会話の安全の決まり）
2. Chrome で公式ページを開き、`img` タグから元画像の URL を取る。fbi.gov の画像は `/image-repository/<名前>.jpeg/@@images/image` が原寸
   （ページに出ている `/@@images/image/large`・`/high` は縮小版。右クリックで保存すると縮小版の webp になる。006 の通気口の写真は原寸 2856 幅、縮小版 768 幅）
3. **複数のファイルは、ページの中で1つの zip にまとめて、1回のクリックで保存する**（2026-11-28 に 006 で成功）。
   - ページの中で `fetch` で原寸を集め、無圧縮の zip（STORE、CRC32 を自前で計算）を `Blob` にする。zip の中の名前は、台帳の `file` のパス（`fbi/mugshot_morris.jpg` など）にする
   - ページに一時的なボタンを置き、`computer` の `left_click` で押す（本当のクリックとして扱われるので、自動ダウンロードの制限に掛からない）。
     ボタンの中で `<a download="<回>_<中身>.zip">` を押す。終わったらボタンを消す
   - 1つずつ `<a download>` を続けて押す方法は、2つ目から Chrome に止められ、確認も出ないことがある
4. ダウンロードから `episodes/<回>/build/materials/` へ展開する（作業用シェルの python の `zipfile`。ダウンロードのフォルダがつながっていなければ、
   ユーザーに PowerShell の `Expand-Archive` を頼む）。展開したら原寸（幅×高さ）を確かめる
5. 台帳の note に、取得日と元の URL を書く

## うまくいかなかったこと

- 2026-11-28：006 の11ファイルをこの手順の3で保存したが、ダウンロードに届いていなかった（上の設定1・2がなかった可能性）。
  保存したタブを閉じると、Chrome の「複数のファイルをダウンロードしようとしています」の確認も消える
- 画面の写し（スクリーンショット）は、ページ全体の記録（手配ページの載り方など）に使う。写真の元画像の代わりにはしない（解像度が足りない）
- 2026-11-28：上の手順で2つ目以降が止まったので、ユーザーが手で保存したら、ページに出ている縮小版（`large`、webp）だった。原寸は手順3の zip で取り直した
- サイトの写しは、ページを拡大（`document.body.style.zoom`）してから撮ると文字が読みやすい（手配ページは 1.35、北テキサス大学の保存ページは中の iframe を 1.6）。
  撮る前にマウスを写す範囲の外へ動かす（矢印が写り込む）。JavaScript の結果に「?」付きの URL を返すと、ツールが結果を止める（パスだけ返す）
